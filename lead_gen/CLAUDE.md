# RIGEL 新規顧客発掘ループエンジニアリング仕様書

## 1. 概要 & 目的

本システムは、ジャノメ卓上ロボットの導入ニーズが高い中小製造業・工場・研究所を関東1都6県を中心に自動リサーチし、高品質なリードリストと最適化されたアプローチメールを生成・記録する自律型ループシステムである。

**送信は行わない。下書きの生成と記録までを担当範囲とする。**（理由は第6章）

---

## 2. 実行ガバナンス（検索条件・提示条件・警告条件）

### ① 検索条件 (Search Criteria)
* **対象地域**: 関東1都6県（東京都・神奈川県・埼玉県・千葉県・茨城県・栃木県・群馬県）に実加工・組立拠点を持つ企業。
* **対象規模**: 従業員数 10名〜300名規模の中小・中堅製造業（卓上ロボット導入の意思決定が早い規模）。**うち50名以下を最優先**とする（`blueprints/target_industries.md` 第4節）。
* **探索トリガー**:
  * 求人情報（「ハンダ付け」「接着・塗布」「ねじ締め」「セル組立」「パート・軽作業急募」）
  * 製造動向ニュース（「工場増設」「新ライン稼働」「自動化推進」「少量多品種対応」）
* **除外条件（ネガティブ判定）**:
  * 人材派遣会社、機械商社・代理店、ソフトウェア受託開発、工場を持たない本社単体、同業競合。
  * 求人サイト・企業DB等の集約サイトそのもの。

### ② 提示条件 (Deliverable Criteria)
* **日次獲得目標**: 新規適格リード **最大10件 / 日**。
* **適合スコア判定**:
  * **Score A**: 具体的工程（塗布/ねじ締め/基板分割/ピック＆プレース）の人手課題が特定できる。
  * **Score B**: 手作業の組立・セル生産ラインがあり、自動化の余地が高い。
  * **Score C**: 製造業だが工程が特定できない。**登録はするが `status: "pending"` とし、日次10件のカウントには含めない。**
* **必須出力項目**:
  1. 企業名・拠点住所
  2. WebサイトURL
  3. 想定課題（「作業省人化」「作業性と品質向上」「生産数増加」のいずれかを特定）
  4. 問い合わせ窓口（フォームURL または 代表/担当メールアドレス）
  5. アプローチメール下書き（300〜400字、売り込み感を抑えた課題解決型）

### ③ 警告条件 (Circuit Breakers & Alerts)
* **最大試行リミット (トークン保護)**:
  * 検索・探索の試行回数が **最大20回** に達した場合、目標未達でもループを即座に中断し正常終了する。
  * 試行のたびに `memories/成果.md` の「試行ログ」へ1行追記すること。**この追記が試行回数の唯一の正本**であり、記憶に頼って数えてはならない。
* **空振り検知 (Dead-loop Prevention)**:
  * 検索クエリで新規リードが **3回連続で0件** だった場合、別県または別業界カテゴリにクエリを自動シフトする。
* **重複・NG企業検知**:
  * ドメインが `memories/blacklist.md` または `memories/leads_database.json` に既存の場合は即スキップ（カウント対象外）。
  * ドメイン未取得の企業は、法人格と空白を除去した**企業名の照合キー**（`name_key`）で重複判定する。
* **アラート記録**:
  * 獲得件数0件終了または致命的エラー時は、`memories/成果.md` に `[WARNING]` フラグと原因を明記する。

## 3. ループ設計図（5項目）

| 項目 | 内容 |
| :--- | :--- |
| **① 読むもの** | `blueprints/rigel_business_concept.md`<br>`blueprints/target_industries.md`<br>`memories/leads_database.json`<br>`memories/成果.md`（直近成果・ノウハウ）<br>`memories/blacklist.md` |
| **② やること** | 1. 探索トリガーをもとにWeb検索<br>2. 適合判定・スコアリング・重複除外<br>3. 企業情報・担当窓口の特定<br>4. 個別課題に合わせたアプローチメール下書き生成<br>5. 成果の保存と引継ぎログ記録 |
| **③ ループ条件** | 新規適格リード（Score A/B）が **10件** に達するまで探索を反復 |
| **④ 停止条件** | 10件達成、または **探索試行回数が20回に到達** した時点で終了 |
| **⑤ いつ動くか** | 平日 毎朝 08:00 JST（GitHub Actions でヘッドレス実行）<br>cron は UTC 判定のため `0 23 * * 0-4`（日〜木 23:00 UTC = 月〜金 08:00 JST） |

## 4. 実行部品（6パーツの役割分担）

### [Part 01] 自動化 (Automation)
* 毎朝定期トリガーから `scripts/run_lead_gen.sh` を介してClaude Codeを非対話（ヘッドレス）モードで起動。
* 実体は `.github/workflows/lead-gen.yml`。実行後、`memories/` の差分を自動コミットする。

### [Part 02] スキル (Skill)
* **求人・製造動向分析**: 「パート・派遣での単純手作業募集」「セル生産ラインの増設」「塗布精度のバラつき課題」から自動化ポテンシャルを特定。
* **ジャノメ卓上ロボット適合判定**: 3軸/4軸の卓上型（基板分割、塗布、ねじ締め、ピック＆プレース）に適合するかを見極める。

### [Part 03] プラグイン (Plugin / Tools)
* `WebSearch`（企業候補の探索）
* `WebFetch`（企業サイトを開いて所在地・事業内容・問い合わせ窓口を特定）
* `Read` / `Write` / `Edit`（メモリの読み書き）
* `Bash(git ...)`（成果のコミット）

### [Part 04] サブエージェント (Sub-Agents)
* `researcher`: 地域（関東1都6県）× 業界 × キーワードで企業候補をWeb探索。
* `lead-filter`: `leads_database.json` および `blacklist.md` と照合して重複を排除し、適合スコア（A/B/C）を付与。
* `copywriter`: スコアA/Bの企業に対し、相手の製造課題に寄り添ったコールドメール（300〜400文字）を生成。

### [Part 05] ワークツリー (Work Tree)
1. **Initialize**: `memories/成果.md`（前回ログ）と `memories/leads_database.json` をロード。
2. **Search Loop**: クエリを実行し企業情報を収集。
3. **Evaluation**: 検索条件・除外条件に基づいてスコアリング。
4. **Draft Generation**: 10件達成または最大20試行まで下書き作成を反復。
5. **Commit**: `leads_database.json` を更新し、日次 `成果.md` を書き出して終了。

### [Part 06] メモリ (Memory)
* `memories/leads_database.json`: 全累積リード（重複チェックマスター）
* `memories/成果.md`: 前日および当日の作業ログ・改善ノウハウ
* `memories/blacklist.md`: 接触NG企業・対象外ドメイン一覧

## 5. leads_database.json のスキーマ

配列。1企業＝1オブジェクト。**重複判定キーは `domain`（無ければ `name_key`）**。

```json
{
  "name_key": "コウエツセイミツ",
  "company": "株式会社〇〇精密",
  "domain": "example.co.jp",
  "pref": "神奈川県",
  "address": "神奈川県〇〇市〇〇1-2-3",
  "url": "https://example.co.jp/",
  "employees": 28,
  "score": "A",
  "issue": "作業省人化",
  "contact": { "type": "form", "value": "https://example.co.jp/contact/" },
  "email_draft": "（300〜400字の本文）",
  "source_query": "神奈川 樹脂 ポッティング 求人",
  "found_at": "2026-09-01",
  "status": "draft",
  "note": ""
}
```

| フィールド | 規約 |
|---|---|
| `name_key` | 全角英数を半角化し、法人格（株式会社・有限会社・合同会社）と空白を除去して大文字化した照合キー |
| `issue` | **「作業省人化」「作業性と品質向上」「生産数増加」の3語のいずれか**。当てはまらない場合はスコアCとし、`note` に実際の課題を書く |
| `status` | `existing`（既存台帳・営業対象外扱い） / `draft`（下書き済・未送信） / `pending`（スコアC・保留） / `sent` / `ng` |
| `contact.type` | `form` / `email` / `""`（不明） |

**`status: "existing"` の71社は `RTS顧客リスト.md` からの初期投入分**であり、
重複判定にのみ使う。ループがこれらを新規として再取得してはならない。

## 6. 運用ルールと制約（必ず守ること）

* **メールは送信しない。** 下書きの生成までとする。コールドメールは特定電子メール法の表示義務（送信者の氏名・住所・受信拒否の通知先）を負い、送信の可否は代表者が判断する。
* **問い合わせフォームへの自動投稿を行わない。** サイト利用規約に抵触する。
* 送付前に**必ず公開情報で事業内容を裏取りする**。「実機をお持ちの御社であれば」等の決めつけは、外すと無礼になる（`RTS顧客リスト.md` 第08章の運用ルール）。
* 取得した企業情報は `leads_database.json` に一元化する。**保管庫側の `RTS顧客リスト.md` は代表者が手で管理する台帳であり、ループは書き換えない。**
* 1回の実行で**新規10件を超えて登録しない**。
* 実行のたびに `memories/成果.md` を上書きせず、**当日分を先頭に追記**する。

## 7. 既知の制約

* **Claude Code on the web の既定環境ではネットワークegressが制限されており、`WebFetch` が `EGRESS_BLOCKED` で失敗する。** `WebSearch` は Anthropic 側で実行されるため利用可能。
* この制約下では必須出力項目④（問い合わせ窓口）が埋まらないため、**本番は GitHub Actions で実行する**。Actions ランナーは外部ネットワークに制限がない。
* web環境で試験する場合は、窓口が埋まらないリードを `status: "pending"`、`contact.type: ""` として登録し、`成果.md` に `[WARNING] WebFetch遮断のため窓口未取得` を記録すること。
