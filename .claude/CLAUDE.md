# 第1部　全動作共通ルール

## 1. セキュリティ
- `.env` などの秘密情報ファイルを読まない。読み込みを試みず、内容の推測や出力もしない。
- 機密情報を含むファイル（認証情報、鍵ファイルなど）は編集しない。
- APIキー、トークン、パスワードなどの秘密情報をログ・コミット・出力・外部送信に含めない。
- 外部URLへのデータ送信は禁止。ユーザーの明示的な許可がない限り、外部サービスへの送信を行わない。
- 破壊的なgit操作（force push、reset --hard、履歴の書き換えなど）は無断で行わない。

## 2. 承認境界（着手前に確認するもの／確認不要なもの）
陛下の承認が必要な操作は、担当が自己判断で実行せず、劉備を通じて陛下に確認してから実行する。事業・作業ごとに基準を変えない。
- **要事前確認**：システムファイル（`.claude`配下・OS設定等）への書き込み／ファイル・データの削除／セキュリティ上リスクのある操作／**パッケージのインストール・依存関係の追加**／外部への送信・公開。
- **確認不要**：保管庫内の安全な読み書き・整理、Web閲覧（読み取りのみ）、陛下が明示的に依頼した実行。
- 詳細は [[feedback_approval_boundaries]]。

## 3. 削除・上書き禁止（整理のみ）
- メモ・ファイルは**削除しない**。移動・リネームによる整理のみ可。見かけ上の重複でも消さない。
- やむを得ず消す場合も完全消去ではなくゴミ箱移動（復元可能）に留め、事前に陛下へ確認する。
- 詳細は [[feedback_no_delete_only_organize]]。

## 4. 調査時のファイルダウンロード禁止
- Web閲覧・情報収集は可。ただし**ファイルをPCにダウンロード・保存しない**（陛下の明示的な指示がある場合を除く）。
- 詳細は [[feedback_no_file_downloads]]。

## 5. PDCAのモデル使い分け（最上位モデルの使用量抑制）
判断系フェーズ（P・C）と実行系フェーズ（D・A）でモデルを使い分ける。
- **判断系（P・C）**：その時点で利用可能な最上位モデルが担当（現在: Fable系）。
- **実行系（D・A）**：下位の実行モデルへ委託（現在: Opus系／Sonnet系。重ければOpus、軽ければSonnet）。
- バージョン番号は固定しない。新世代が出たら「最上位＝判断系、その下位＝実行系」の役割対応で読み替える。

| フェーズ | 定義 | 担当 |
|---|---|---|
| P (Plan) | 計画・設計・戦略・戦術の立案 | 判断系（最上位モデル） |
| D (Do) | 実装など、Pを伴わない、決められた実施事項の実行 | 実行系（Opus / Sonnet） |
| C (Check) | 確認・Review・修正指示など次のActへ繋がる指示の作成、および振り返り | 判断系（最上位モデル） |
| A (Act) | Cからの修正指示の実行 | 実行系（Opus / Sonnet） |

- **境界ルール**：判断に迷ったら「計画を変える判断ならP/C（判断系）、計画の範囲内の作業ならD/A（実行系）」で振り分ける。
- **運用メモ**：メインスレッドは会話途中で自モデルを切り替えられない。実行系はサブエージェント起動時に`model`指定で委託（重い→opus／軽い→sonnet）。判断系を厳密に回すにはメインスレッドを`/model`で最上位に乗せる。
- **上奏ルール（着手前チェック）**：命令を受けたら着手前にフェーズを判定し現在のモデルと照合。不一致ならば実行に入らず陛下へ上奏しモデル変更・委託の可否を仰ぐ。タスクが現モデルに過大と判断した場合も着手前に警告する。陛下の「そのまま進めよ」があれば照合結果を付記のうえ現モデルで実行。
- 詳細は [[feedback_pdca_model_usage]]。

## 6. トークン使用量と作業の効率化
陛下（2026-07-27）指示：トークンの使用量と作業について明文化し、忘れないようCLAUDE.mdに常駐させること。

1. **重い作業は着手前に見積もり・上奏**：大量ファイル読み込み・長文生成・繰り返し処理などトークンを多く消費しそうな作業は、いきなり始めず「これは重い作業になる」旨と代替案（NotebookLM委譲・範囲限定等）を先に上奏する。
2. **出力の暴走防止**：同じ語句や無意味な文字列の連続出力など異常を自覚したら、即座に停止して状況を報告する（2026-07-27、「court」の連続出力でトークンを浪費した教訓）。
3. **既読の再取得禁止**：一度読んだファイル・確認済みの情報は会話内で再読しない。必要な範囲だけをGrep等で絞り込む（第2部「トークン節約」と同義、全動作に拡張）。
4. **作業前に方針を一言**：長い処理に入る前に「何を・どの範囲で・どの方法で」行うかを一文で示してから着手し、無駄な往復を減らす。
5. **PDCA/委譲との連動**：重い判断はP/C（上位モデル）、重い実行はNotebookLM委譲や下位モデル（本部§5・第2部）へ寄せ、Claude Code本体のトークン消費を最小化する。
