# RIGEL 文書作成ルール（契約書・帳票・A4文書）

> **位置づけ**：[[プレゼンフォーマット]]（v0.2）はスライド（16:9横）向けの規定。
> 本ノートは、**契約書・注文書・見積書など「A4縦のビジネス文書」**に同じブランド規定を適用するための派生ルール。
> 次回以降、契約書・帳票類を作成する際は**必ず本ノートと照合**すること。

---

## 0. 適用範囲

| 文書種別 | レイアウト | 適用ルール |
|---|---|---|
| 提案資料・説明会資料 | 16:9 横（1920×1080） | [[プレゼンフォーマット]] |
| **契約書・注文書・見積書・請求書** | **A4 縦（595×842pt）** | **本ノート** |

**判断基準**：署名・押印して相手方と取り交わす文書、または保管・提出を前提とする文書は**A4縦**。会議で投影して説明する文書は16:9横。

---

## 1. カラー（プレゼンフォーマット v0.2 と共通）

| 用途 | 値 |
|---|---|
| メイン／アクセント | ジュビリーブルー `#026881` |
| ライト | `#74ACBA` |
| ダーク（見出し文字） | `#014B5D` |
| インク（本文） | `#17181A` |
| サブ文字 | `#6B6E73` |
| 罫線 | `#E3E1DB` |
| 補足ボックス背景 | `#F2F7F9` |

### ⚠ 用紙色だけは例外
- プレゼンの背景色はオフホワイト `#F7F6F3` だが、**契約書・帳票の用紙は白 `#FFFFFF`** とする。
- 理由：署名・押印して印刷する文書で全面に地色を敷くと、家庭用・事業所用プリンタで用紙全面にインクが乗り、体裁と印刷コストの両面で不利になるため。
- **この1点のみプレゼンフォーマットから意図的に逸脱している。** それ以外の色は完全に共通。

### ⚠ 旧規定との衝突（解決済み）
- [[RIGEL Presentation Style Skill]] には「メインカラー `#0070C0` / フォント Aptos」との記載があるが、**これは旧版**。
- [[プレゼンフォーマット]] v0.2（2026-07-23）の改訂履歴に「**コーポレートカラーを正式色 `#026881` に統一**」と明記されており、[[ロゴ]]ノートでも `#026881` が「絶対に変更不可」とされている。
- **採用するのは `#026881`。** `#0070C0` は使用しない。旧ノートは未整理のまま残っているので、参照しないよう注意する。

---

## 2. ロゴ

- 使用するのは [[RIGEL(Jubilee Blue).png]] のみ。他バリエーションは使用しない。
- **全ページ右上に固定配置**（プレゼンと同一ルール）。
- A4縦での推奨寸法：**高さ12mm**／用紙右端から**18mm**／用紙上端から**9mm**。
- 元画像は 2048×2048 で周囲に余白と極薄のアーティファクトがある。**アルファ値25を閾値にトリミングしてから使用する**こと（そのまま貼ると余白のぶん小さく見える）。
- 色・形状の変更、再配色、要素の分離は禁止。

---

## 3. タイポグラフィ

- フォント：**Noto Sans JP**（プレゼンと共通）。フォールバックに Yu Gothic → Hiragino Sans → IPAexGothic を並べる。
- A4縦でのサイズ目安

| 要素 | サイズ | ウェイト |
|---|---|---|
| 文書表題 | 20pt（字間 .45em） | 900 |
| 条見出し | 10.5pt | 700（色 `#014B5D`） |
| 本文 | 10pt | 400 |
| 補足・メタ情報 | 8pt | 400（色 `#6B6E73`） |

- 条見出しには**左に3.5pt のアクセント罫**（`#026881`）を付ける。
- 金額・重要数値は太字＋`#014B5D`。

---

## 4. レイアウト

- 用紙：A4縦。余白 上28mm／左右18mm／下20mm（上マージンはロゴのぶん広くとる）。
- 表題は中央寄せ、直下にメタ情報（会社名／用途／版数／日付）を置き、**2ptのアクセント罫**で本文と区切る。
- 署名欄は左に2ptの罫線を立て、押印欄は破線の円（13mm）で示す。
- **条文の途中改ページは許容する**（`page-break-inside: avoid` を条単位でかけると、長い条の前に大きな空白が生じるため）。ただし
  - 条見出しだけが頁末に残らないよう `break-after: avoid` を見出しに指定
  - `orphans: 2; widows: 2` を指定
  - 署名欄（`.closing` / `.sign-area`）は分割禁止

---

## 5. 社内メモの扱い

- 契約書ファイルには、社内向けの「運用メモ」（法令の解説・交渉時の注意点など）を末尾に持たせてよい。
- ただし **`@media print` で必ず非表示**にし、PDF・印刷物には出力しないこと。相手方に渡る成果物に社内検討の内容を混入させない。
- 同様に、ファイル冒頭の「用途バナー」（発注用／受注用の取り違え防止）も印刷時は非表示にする。

---

## 6. PDF生成の手順と既知の落とし穴

生成は **Chromium ヘッドレスの `--print-to-pdf`** を使う（`@page` のCSSがそのまま効く）。

```
chrome --headless --disable-gpu --no-sandbox --no-pdf-header-footer \
       --print-to-pdf=出力.pdf file:///絶対パス/入力.html
```

### 落とし穴①：`position: fixed` のロゴはPDFに出ない
- 画面表示では効くが、`--print-to-pdf` では**1ページ目にしか描かれず、しかも本文に重なる**。
- **対策**：印刷CSSで `.brand-logo { display: none }` としたうえで、**PDF生成後に全ページへロゴを焼き込む**。
- 焼き込みスクリプトの要点：reportlab で「ロゴのみのA4オーバーレイPDF」を作り、pypdf の `merge_page()` で全ページに重ねる。

### 落とし穴②：Noto CJK は一部の文字が別のコードポイントで埋め込まれる
- 「月・日・用・乙・立」など、**康熙部首と字形が同じ文字**が、PDFのテキスト抽出時に部首側のコードポイント（U+2F47 等）で返る。
- **見た目・印刷は正常**だが、PDFビューアでの検索・コピーが一部効かない。
- 検証時に「文字列が見つからない」と判定しても、**それは不具合とは限らない**。レンダリング画像で目視確認すること。
- どうしても検索性を優先する文書では IPA明朝／IPAゴシックを使うと解消する（ただしブランド規定から外れる）。

### 落とし穴③：環境にフォントがないと豆腐になる
- Noto Sans JP が無い環境では `fonts-noto-cjk` を導入してから生成する。
- 生成後は**必ずページ画像に描き出して目視確認**する。テキスト抽出だけで「OK」と判断しない。

## 7. 検証チェックリスト（PDF出力後に毎回行う）

- [ ] ページサイズが 595×842pt（A4縦）である
- [ ] **全ページ**の右上にロゴがある（1ページ目だけになっていないか）
- [ ] ロゴが本文・表題に重なっていない
- [ ] 日本語が豆腐になっていない（**画像で目視**）
- [ ] 社内用メモ・用途バナーが出力されていない
- [ ] 大きな空白ページ・不自然な改ページがない
- [ ] 金額・日付・相手方名称が意図どおり
