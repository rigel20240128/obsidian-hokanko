# RIGEL 資料作成ルール（統合版 v1.0）

> **本書がRIGELの資料作成における唯一の正本である。**
> `1.文書作成ルール` フォルダ内に分散していた6ファイルの内容を1本に統合した（統合元は末尾「附属A」参照。原本は削除せず保存）。
> 「RIGELフォーマットで◯◯を作って」と指示されたら、本書のすべてを満たす成果物を作る。
>
> **対象**：印刷/PDF文書（契約書・提案書・仕様書・報告書）と、スライド資料（pptx・16:9）の両方。
> 第1章〜第3章は**全成果物に共通の絶対規定**。第4章が文書系、第5章〜第7章がスライド系の個別規定。

# 第1章　ブランド絶対規定（変更不可）

## 1.1 会社ロゴ

- 使用ロゴ：RIGEL_logo のみ**。他には一切使用しない。[[RIGEL_logo.pdf]]
- 保管場所：`2.社内規定(RIGEL)/1.プロフィール/RIGEL_logo
- ロゴ構成：セリフ体の「RIGEL」ワードマーク（Rの中に釣り針＝フックのモチーフ）＋タグライン **"Hook the Future"** ＋コンパス/八方星シンボル。
- **色・形状は完全固定。再配色・変形・要素の分離・トーン変更は絶対に禁止。**
- 配置：**全ページ右上に固定**（文書・スライドとも、表紙も本編も右上で統一。中央大きく配置はしない）。
- 濃色背景（章扉など）：矩形の白プレートは使わず、**透明背景のまま輪郭に沿って白フチ（約5px相当）**を付けてコントラストを確保する。
- クリアスペース：ロゴ高さの0.5倍以上を四方に確保。
- 適用範囲：提案資料・提出ドキュメント全てにこのロゴを使用。**RIGEL事業以外（点心・古民家＝源氏車事業）は本規定の対象外。**

## 1.2 コーポレートカラー「ジュビリーブルー」

東京ディズニーシー25周年イベント「スパークリング・ジュビリー」で命名された特別な青。**絶対に変更不可。近似色で代用しない。**

| 表色系 | 値 |
|---|---|
| HTML/HEX | **#026881** |
| RGB | **R:2 / G:104 / B:129** |
| CMYK | **C:89 / M:56 / Y:44 / K:1** |

※印刷（CMYK）・画面（RGB/HEX）で上記値を厳守。

## 1.3 カラーパレット（確定値・全成果物共通）

同じ青の**濃淡（モノクロマティック）**で統一し、一体感と高級感を両立する。

### 運用ルール（2026-07-23 陛下ご決定）
- **図表・グラフの配色順序**：`#026881` → `#74ACBA` → `#C7CBD3` の順で固定。強調したい1系列のみ例外的に `#E8622C`。多色使いは避ける。
- **アクセントカラー**：基本は**ジュビリーブルー単色で統一**。オレンジはセカンダリカラーとして多用せず、重要数値・注意喚起のごく一部に極小面積で使うのみ。
- **背景色は資料全体で最大1〜2色**（オフホワイト＋反転の濃色）に絞る。1スライドにつき強調は1〜2箇所。
- 本文は青くしない（近似ブラック＝可読性優先）。純黒は使わない。
- 別色相の多用は禁止。

## 1.4 タイポグラフィ

- フォント：**Noto Sans JP**（ウェイト 300 / 400 / 500 / 700 / 900 を使い分け）。
  - 文書系で無い場合のフォールバック：Yu Gothic / Hiragino 等。
- **装飾フォント・手書き風フォントは使用しない。**

### タイプスケール（スライド：1920×1080px基準）

| 要素 | サイズ | ウェイト |
|---|---|---|
| タイトル | 68〜88px | 700〜900 |
| サブタイトル | 40px | 500 |
| 本文 | 32px（最小24px） | 400 |
| 補足（small） | 24px | 400 |
| kicker（章名ラベル） | 22px | 500 |
| 章番号・KPI数値 | 110〜200px | 900（特大） |

- 本文は**最小24pxを死守**（会議室スクリーン視認性の下限）。

# 第2章　共通デザイン思想

- **思想**：装飾は最小。情報の階層とタイポグラフィで魅せる。**「1000のNoに1つのYes」**。
- **参照する上質さ**：Apple・キーエンス・トヨタ級の洗練。余白・タイポ・秩序で魅せる。
- **トーン**：日本語、説明的・丁寧。章タイトルのみ端的な体言止め。想定読者は経営層。
- **1スライド1メッセージ**。文字量は最大10行程度。余白を広く取る。

## 2.1 禁止事項（例外なし）

- ドロップシャドウ／3D効果／グラデーション
- 章扉・本文背景へのストックフォト／テクスチャ
- 情報の階層を「色数」で表現すること（ウェイト・サイズ・余白のみで秩序を作る）
- 過度な装飾／派手なアニメーション／安価な印象を与える表現
- 装飾用の余計な図形・アイコン・数値の追加

## 2.2 推奨する図版

技術図／3D CAD画像／工程図／比較表。

## 2.3 内部／外部の切替（基本方針⑳）

**外部向け成果物**（提案書・プレゼン・銀行/行政提出資料・取引先メール・SNS投稿等）は、三国志の呼称・「陛下」表記を一切使わず、正式名称「株式会社RIGEL」・代表者「佐藤貴久」等の実名で出力する。出力直前に内部/外部を必ず自問する。

## 3.1 情報ソース

- 会社の事実（社名・代表者・住所・事業）は保管庫内のRIGEL資料（`RIGEL事業概要.md` 等）から引く。
  - 会社名：株式会社RIGEL／代表者：佐藤貴久／所在地：千葉県柏市／設立目標：2026年10月29日／資本金：300万円
- 案件固有の資料（例：契約条件のxlsx）があれば**必ず参照し、その内容を正としてデータを反映する**。
- **判断前の確認徹底**：「未確定・不足」と上奏する前に、関連しそうなvault内mdファイルを実際に確認してから発言する。

## 3.2 納品フロー（印刷/PDF文書）

1. HTMLで組む（ロゴはbase64で埋め込み＝単一ファイルで完結）。
2. Edgeヘッドレスで **A4 PDF** 生成（`--headless=new --print-to-pdf --no-pdf-header-footer`）。
3. **PDFは自動でDownloadsフォルダへ保存**（都度確認しない）。元フォルダにも残す。
4. 契約等の法的文書は、末尾または連絡で**「締結前の専門家確認」を必ず添える**（本作成物は法的助言ではない）。

## 3.3 トークン節約ルール

- 重い分析・複数案生成は**NotebookLMへ委譲**（ブラウザ操作）。Claude Code側は入力準備・指示送信・結果保存/要約のみ担当。
- 読み込みファイルは自ら絞り込む（Grepで該当箇所特定→必要範囲のみRead、既読は再読しない）。

# 第4章　印刷/PDF文書の規定（契約書・提案書・仕様書・報告書）

## 4.1 書式・ページ規定

- **用紙は必ずA4**（`@page{ size:A4 }`）。余白は用途に応じ最小限（実印刷するなら端7〜8mm確保、PDF閲覧/入稿なら5mm可）。
- **章（条・セクション）の途中でページを割らない。区切りは必ず章の境目。**
  - CSS：章ブロックに `break-inside:avoid; page-break-inside:avoid;`、見出しに `break-after:avoid;`、表・署名欄等の塊にも `break-inside:avoid;`。
- ページ末に隙間が出ても、章は途中で切らない（余白は許容）。
- 隙間を減らしたいときは**文言を変えず**、行間・余白（レイアウト）で圧縮する。
  - ※契約書等の法的文書は「**文は正、レイアウトを合わせる**」。句読点・文言を体裁目的で変えない。

## 4.2 レイアウトの型

| 部位 | 規定 |
|---|---|
| ヘッダー | 右上にロゴのみ（重複する文字ラベルは置かない）＋直下に区切り線（`#026881`） |
| タイトル | 中央・太字（近似ブラック）。必要なら下にサブ（当事者名など・`#6B6E73`） |
| 本文 | 章（第N条／セクション）を積む。各章は見出し（`#014B5D`・左に `#026881` のアクセントバー）＋本文 |
| 表 | ヘッダー行は `#026881` 塗り・白文字 |
| 署名欄（契約書） | 末尾に甲/乙を2カラム、住所・法人名・代表者・押印欄 |
| フッター | 文書名／日付を小さく（`#6B6E73`） |

# 第5章　スライド資料の規定（pptx・16:9）

## 5.1 画面仕様・レイアウト共通ルール

- サイズ：**16:9（1920×1080px）**
- 全スライド**左上に kicker**（章名・セクション名）を配置
- 会社ロゴは**全ページ右上**に固定配置（1.1参照）
- 各スライド**右下にページ番号**（`n / 総数` 表記可）
- タイトルは**左寄せ・上部**、下部に意図的な余白を残す構成
- **章の扉（差し込みページ）は反転デザイン**（`#014B5D` 単色背景＋白文字）で統一。**写真・図版は一切敷かない**。章番号＋章タイトルのみ。

## 5.2 スライド型（枚数非依存・レイアウト部品）

枚数に依存しない。以下の型を必要な数だけ組み合わせる。

**骨格（必須の3型）**
- **表紙** — タイトル / サブ / 会社名 / 日付 / ロゴ
- **目次（アジェンダ）** — 章立てを番号付きで一覧
- **まとめ・締め** — 要点の再確認＋次のアクション（お問い合わせ・ロゴ）

**中身（必要なだけ繰り返す本文型）**
- **章の扉（差し込み）** — 章番号＋章タイトル。反転・ジュビリーブルーダーク。章の数だけ挿入
- **本文（箇条書き）** — 2〜4カラムの並列項目、または縦積みの論点
- **図表・グラフ** — 棒／折れ線／円 ＋ 左右2分割の説明文
- **比較・対比** — Before / After や A / B の2カラム
- **KPI 数値強調** — 特大数字を主役に、1〜4指標
- **プロセス／ステップ** — 横並びのSTEP、区切り罫線つき
- **スケジュール／工程** — ガント風のグリッド

**汎用ルール**
- 章の扉は章の数だけ挿入し、番号（01, 02, 03…）を自動連番にする
- **目次の項目数と章の扉の数は常に一致させる**
- 型を増減しても、カラー・タイポ・レイアウト規則は変えない

## 5.3 実装メモ

- deck-stage コンポーネントで 1920×1080 スライドを構築。
- 各 `<section>` に `data-label` と `data-speaker-notes` を付与。
- スタイルはインライン。
- 最終出力は PowerPoint(pptx) 編集を想定。

# 第7章　デザイン4案（陛下ご裁可待ち・未確定）

> NotebookLM が生成したたたき台（2026-07-23）。**全案とも第1章のブランド絶対規定を遵守するため、どれを選んでもRIGELのアイデンティティは一貫して保たれる。**
> 現時点では**未確定**。陛下が「全社1案統一」か「事業別使い分け」かをご決定のうえ、軸となる案を本書へ正式反映する。

## 7.1 A案：ミニマル・タイポ主導型（Minimal Typography）
余白を「思考を核心へ導く空間」と定義。情報を極限まで間引く。
- **設計思想**：Apple級の洗練。ジャンプ率（Title 88px と Body 32px の対比等）で視覚的フックを作る
- **セーフエリア**：全端から**15%以上**のマージンを絶対余白として確保、要素を中央に凝縮
- **カラー比率**：背景 `#F7F6F3` を**90%以上**、ジュビリーブルーはテキスト強調のみ
- **推奨用途**：⑥会社設立・経営管理（金融機関・投資家向け）、②FA設備設計（ハイエンドな概念提案）
- **限界**：技術的詳細や多角データを1枚に詰めるのは不向き

## 7.2 B案：構造的システム・グリッド型（Structural Grid）
複雑なエンジニアリングデータ・多層ロジックを迷いなく伝える「構造化」特化。
- **設計思想**：キーエンス級の合理的・正確な伝達。**12カラムのグリッド**で全要素をミリ単位整列
- **カラー比率**：罫線 `#E3E1DB` を境界線としてのみ使い論理分割、背景はオフホワイト基調
- **タイポグラフィ**：Noto Sans JP **400/500/700** を主軸
- **推奨用途**：②FA設備設計の技術解説、①RTS事業のカリキュラム説明
- **評価**：誠実さ・専門性で安心感。論理で納得させる型

## 7.3 C案：大判ビジュアル・ストーリーテリング型（Visual Storytelling）
ブランドの「質」を直感的に伝える感情訴求型。
- **設計思想**：高品質ビジュアルを視覚的フックとして大胆配置。トリミングで焦点を絞り余白と対比
- **カラー比率**：ライト `#74ACBA` を背景ブロックに、ミッドグレー `#C7CBD3` は図表補助のみ
- **タイポグラフィ**：Noto Sans JP **300** の洗練キャプションを多用
- **推奨用途**：⑤古民家活用（源氏車）、④飲食業界向けAI・IoTの空間提案
- **評価**：共感・憧れを醸成。緻密なロジック説明には不向き

## 7.4 D案：モダン・ベニヤ・ダッシュボード型（Modern Dashboard）
AI社員が生成するリアルタイムデータを即座に把握する高機能インターフェース型。
- **設計思想**：1画面で複数KPIを俯瞰するモジュール化配置（Bento Grid）。情報の「即時把握」最優先
- **カラー比率**：ジュビリーブルーを枠・ヘッダーに使い情報区分、最重要数値のみ `#E8622C` を極小面積
- **タイポグラフィ**：数値（KPI）を **110〜200px / Weight 900** で大胆配置
- **推奨用途**：③FA設備営業代行の進捗報告、全事業のKPI管理・定例報告
- **評価**：意思決定を高速化。情緒的訴求力は低め。階層管理を誤ると情報過多のリスク

## 7.5 総合比較マトリクス

| 案 | 設計思想 | 情報密度 | 向く主な事業 | 長所 | 短所 |
|---|---|---|---|---|---|
| A ミニマル | 余白と思考の空間 | 低 | ⑥会社設立、②高級提案 | 圧倒的な洗練度と高級感 | 情報量が多いと成立しない |
| B グリッド | 論理的秩序と構造化 | 高 | ①RTS、②技術解説 | 誠実な信頼感と高い網羅性 | 遊びが少なく堅苦しくなる |
| C ビジュアル | 感情と物語への訴求 | 中 | ⑤源氏車、④飲食AI | 瞬時のイメージ共有と共感 | 論理的緻密さの提示が困難 |
| D ダッシュボード | 機能美とデータ駆動 | 高 | ③営業代行、KPI管理 | 即時把握性と先進的機能美 | 階層管理を誤ると情報過多 |

## 7.6 諸葛亮の精査メモ

- NotebookLMは**単一案への統一ではなく「事業ごとに型を使い分ける」**方針を推奨。6事業の性質差（技術系＝B/D、ブランド系＝A/C）を踏まえると理にかなう。

# 営業提案プレゼン作成スキル

経営層向けの「営業・提案」プレゼン資料を、大手企業（Apple / キーエンス / トヨタ）級の
洗練されたトーンで作成するためのプロンプト／仕様。

## 使い方（プロンプト例）

> 営業・提案向けのパワーポイント基本テンプレートを作って。
> 想定読者は経営層、日本語、16:9（1920×1080）、説明的で丁寧な見出しトーン。
> Apple・キーエンス・トヨタなど大手のスタイリッシュな資料を参照し、
> 余白・タイポ・秩序で魅せる構成に。右上に会社ロゴを全ページ配置。
> PowerPoint(pptx)として書き出せるようにして。

## デザイン方針

- **思想**: 装飾は最小。情報の階層とタイポグラフィで魅せる。1000のNoに1つのYes。
- **言語 / トーン**: 日本語。説明的・丁寧。章タイトルのみ端的な体言止め。
- **サイズ**: 16:9 / 1920×1080。本文は最小24px、なるべく大きく。

## カラーパレット

| 用途         | 値                       |
| ---------- | ----------------------- |
| 背景（明）      | オフホワイト `#F7F6F3`        |
| インク（文字）    | 近似ブラック `#17181A`        |
| サブ文字       | `#6B6E73`               |
| アクセント      | RIGELジュビリーブルー `#026881` |
| 罫線         | `#E3E1DB`               |
| 差し込み（章扉）背景 | ジュビリーブルー・ダーク `#014B5D`  |
| 章扉アクセント    | ジュビリーブルー・ライト `#74ACBA`  |

- 背景色は資料全体で最大1〜2色。
- 章の扉（差し込みページ）は反転デザインで統一。

## フォント / タイプスケール

- Noto Sans JP（300/400/500/700/900）。
- title 68〜88 / subtitle 40 / body 32 / small 24 / kicker 22。
- 章番号・KPI数値は 110〜200px の特大ウェイト（900）。

## スライド構成（枚数非依存 / 汎用）

このスキルは**枚数に依存しない**。以下の「スライド型（レイアウト部品）」を
必要な数だけ組み合わせて構成する。5枚でも50枚でも同じ型を再利用すればよい。

### 骨格（必須の3型）
- **表紙** — タイトル / サブ / 会社名 / 日付 / ロゴ
- **目次（アジェンダ）** — 章立てを番号付きで一覧（項目数は自由）
- **まとめ・締め** — 要点の再確認＋次のアクション（お問い合わせ・ロゴ）

### 中身（必要なだけ繰り返す本文型）
- **章の扉（差し込み）** — 章番号＋章タイトル。反転・ディズニー青。章の数だけ挿入
- **本文（箇条書き）** — 2〜4カラムの並列項目、または縦積みの論点
- **図表・グラフ** — 棒／折れ線／円 ＋ 左右2分割の説明文
- **比較・対比** — Before / After や A / B の2カラム
- **KPI 数値強調** — 特大数字を主役に、1〜4指標
- **プロセス / ステップ** — 横並びの STEP、区切り罫線つき
- **スケジュール / 工程** — ガント風のグリッド

### 汎用ルール
- 章の扉は「章の数だけ」挿入し、番号（01, 02, 03…）を自動連番にする。
- 目次の項目数と章の扉の数は常に一致させる。
- ページ番号は総枚数に応じて振り直す（`n / 総数` 表記も可）。
- 型を増減しても、カラー・タイポ・レイアウト規則は変えない。
- 分量が増える場合も背景色は1〜2色に固定し、章扉の反転で区切る。

## レイアウト規則

- 全スライド左上に kicker（章名・セクション名）。
- **会社ロゴは全ページ右上**に配置。濃色スライドは白プレートに載せる。
- 各スライド右下にページ番号。
- タイトルは左寄せ・上部、下部に余白を残す構図。
- スライド区切り（章の扉）は反転（濃色背景・白文字）で統一。

## 実装メモ

- deck-stage コンポーネントで 1920×1080 スライドを構築。
- 各 `<section>` に `data-label` と `data-speaker-notes` を付与。
- スタイルはインライン。装飾用の余計な図形・アイコン・数値は足さない。
- 最終出力は PowerPoint(pptx) 編集を想定。
