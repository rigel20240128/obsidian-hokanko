# オリジナルアイコン作成ルール（統合版）

旧2ファイル（線画方式／シルエット方式）を統合し、比較・精査した上で正式ルールとして統一したもの。
旧ファイルは削除せず `9.控え/` に移動して保存している（削除禁止ルールに基づく）。

## 0. 統合の経緯・比較サマリ

旧2ファイルは、同じ「社内ドキュメント用アイコン」を対象としながら、根本的に異なる2方式を定めており、そのままでは併用できない状態だった。

| | 線画方式（旧版1） | シルエット方式（旧版2・11分後に作成） |
|---|---|---|
| 表現方法 | 線画（stroke、24x24グリッド、線幅1.5〜2） | シルエット塗りつぶし（五輪ピクトグラム風） |
| 色 | 単色＝企業カラー1色（例示は#2563EBでRIGEL正式カラーではない） | テーマ単位で色管理。RIGELカラーは意図的に不使用 |
| 余白規定 | 周囲10%セーフエリアを明記 | 規定なし |
| 枠・背景 | 言及なし | 「枠で囲わない・背景を敷かない」を明記 |

### 良い点・悪い点の精査

**線画方式**
- 良い点：Web・デジタルUIとの親和性が高い（実際、現行ホームページ [rigel-homepage/index.html] のアイコンはこの方式で作成済み）。グリッド・線幅・余白の仕様が具体的で再現しやすい。
- 悪い点：色管理の仕組みがなく、テーマが増えると破綻しやすい。細い線は印刷・小サイズで潰れやすい。

**シルエット方式**
- 良い点：テーマ別カラー表による一元管理・重複チェックの仕組みがあり拡張に強い。RIGELカラー(#026881)をアイコンから意図的に分離しており、ブランドカラー希薄化を防ぐ設計思想と整合的。塗りつぶしシルエットは印刷・小サイズでの視認性が線画より高く、社内文書（A4印刷が基本）の実務に合う。
- 悪い点：作成時点でテーマ別カラー表が空欄で未運用。余白規定がなく統一感にブレが出る恐れ。細かいモチーフをシルエットのみで表現するのは線画より難易度が高い。

### 採用方針

**社内ドキュメント用アイコンは「シルエット方式」を正式ルールとして採用する。** 印刷物中心の運用実態（A4固定PDF文書がRIGELの標準成果物）に適しており、色管理の仕組みも将来の拡張に耐えるため。線画方式の優れていた点（セーフエリア規定・運用ノウハウ）は本統合版に取り込んだ。

> 注：現行のホームページ（rigel-homepage/index.html）のアイコンは線画方式で作成済みだが、ホームページは「社内ドキュメント」ではなく対外公開の別カテゴリのため、本ルールの対象外とする。ホームページのアイコン方式を揃えるかどうかは別途ご判断いただきたい。

## 1. デザイン原則（固定・全アイコン共通）

| 項目 | ルール |
|---|---|
| 表現方法 | シルエット塗りつぶし中心（オリンピックのピクトグラム風）。線画・グラデーションは使わない |
| 視認性 | 遠くから見ても一目で意味がわかるシンプルさを優先する |
| 画角比率 | 1:1（正方形キャンバス、24x24グリッド基準） |
| 余白 | 周囲に10%程度のセーフエリアを確保し、モチーフは中央配置（線画方式より継承） |
| 枠・背景 | 周囲を枠で囲わない／四角い背景を敷かない（モチーフ自体のシルエットのみ） |
| グラデーション | 使用しない（単色の塗りのみ） |
| RIGELカラー | 使用しない（コーポレートカラー#026881とアイコンカラーは分離する） |
| 構図 | モチーフは1〜2要素に絞る。情報を詰め込みすぎない |

## 2. カラールール

- 色による統一感は「テーマ単位」で管理する。
- 1テーマ＝1色（固定）。同じテーマ内の全アイコンは同じ色を使う。
- 新しいテーマを作る場合は、下表に追記してから作成に入ること（RIGELカラーおよび既存テーマの色と重複しない色を選ぶ）。
- テーマ数が増えてきたら、色が近すぎないか（遠目で見分けがつくか）を都度チェックする。

### テーマ別カラー一覧

| テーマ名 | 割当カラー（HEX） | 用途例 | 備考 |
|---|---|---|---|
| （例）文書作成ルール | #未定 | 文書作成ルール関連アイコン | |
| RTS利用フロー | #2F80ED（明るい青） | RTS用プレゼン資料の掲載イラスト（①製品到着②組立③トラブル学習） | RIGELティール系(#026881/#74ACBA)と混同しない純粋な青を選定。ファイルは `RTS利用フロー/` フォルダに格納 |
| | | | |

> 未記入のテーマは色未確定。新規テーマ追加時は必ずこの表を更新する。

## 3. 依頼時の入力項目（都度入力）

| 入力項目 | 説明 | 記入例 |
|---|---|---|
| ① テーマ | どのカテゴリ（＝どの色）に属するか | 文書作成ルール |
| ② 用途 | アイコンの意味・使われるシーン | 注意喚起／完了／ダウンロード／承認待ち |
| ③ モチーフ | 何を描くか（1〜2要素） | 書類とチェックマーク |
| ④ アイコン名 | ファイル名・呼び名 | icon_approved |
| ⑤ 特記事項（任意） | 向き・強調点など | 「もう少し太めに」等 |

## 4. 依頼用の定型文（コピペして使う）

```
[デザイン原則]の条件で、以下のアイコンを作成してください。
色は[テーマ別カラー一覧]の「〇〇」テーマの色（#〇〇〇〇〇〇）を使用してください。

テーマ：〇〇
用途：〇〇
モチーフ：〇〇
アイコン名：〇〇
特記事項：〇〇
```

## 5. 使用例

```
テーマ：文書作成ルール
用途：承認完了
モチーフ：書類とチェックマーク
アイコン名：icon_approved
特記事項：チェックマークをやや大きめに
```

## 6. 運用メモ

- 迷ったら「オリンピックのピクトグラム」を基準に、シルエットだけで意味が伝わるかを確認する。
- 最初の1〜2個を作った後、「このテイストを基準に」と伝えると以降のブレがさらに減る（線画方式より継承）。
- 用途カテゴリの一覧を先に洗い出しておくと、抜け漏れなく作成できる（線画方式より継承）。
- テーマ数が増えてきたら、色が近すぎないか（遠目で見分けがつくか）を都度チェックする。
