# Claude Code 24時間稼働・低トークン消費ガイド

Claude Codeを長時間稼働させると、過去のやり取り（コンテキスト）が蓄積し、雪だるま式にトークンを消費してしまいます。
これを防ぎ、効率的かつ低コストで運用するための仕組みと最適な作業についてまとめました。

## 1. トークン消費を抑える3つの仕組み

### ① コンテキストの定期的な圧縮とリセット
会話が長くなってきたら、以下のコマンドや手法を用いてコンテキストを整理します。これにより1回あたりのトークン消費を抑えられます。
- **コマンドの利用**: `/compact` コマンドを使用してコンテキストを圧縮します。
- **セッション管理**: タスクごとにセッションをリセットします。

### ② Skill機能の活用
よく発生する定型作業は「Skill」として登録します。
- **メリット**: 普段はタイトルだけが読み込まれ、必要な時だけ詳しい手順が呼び出されるため、無駄なトークン消費を防ぐことができます。

### ③ バッチ処理への移行
リアルタイムでの応答が不要なタスクに適用します。
- **メリット**: 一括で処理を予約する「バッチ処理」を活用することで、APIの利用コストを大幅に（最大50%程度）削減できます。

---

## 2. 24時間稼働に最適で低燃費な作業

トークンを抑えるための基本原則は、**「過去の膨大な前提知識を常に保持し続ける必要がない、細分化された作業」**を選ぶことです。

### ① 独立したモジュールのテストコード生成
ファイル単体で完結するテストコードの作成を行います。
- **理由**: プロジェクト全体の文脈を読み込ませる必要がないため、低コンテキスト・低コストで並列処理が可能です。

### ② 定型データのクレンジング・ログ解析
決まったフォーマットのデータ処理を行います。（例：システムログからエラーだけを抽出、顧客データの表記揺れを修正など）
- **理由**: Skillとしてルールを定義しておけば、最小限のトークンで自動化が可能です。

### ③ ドキュメントの翻訳や定型フォーマット化
マニュアルの多言語化や、古いコードのコメントを最新のドキュメント形式に書き換える作業などを行います。
- **理由**: ファイル単位で処理を区切ることができるため、トークン消費を抑えつつ24時間稼働させやすいタスクです。
