# 2. 仕様確定による技術課題の変化（重要）

## 2-1. オートキュー問題は「消滅」した

v1で最大の課題は「任意の盤の、任意の曲位置に針を落とす」ことだった。
7インチシングルに確定したことで、この課題は**構造的に消える**。

- **7インチシングル＝片面1曲**。だから「曲の頭出し」＝「盤の頭出し」であり、曲位置のシークが要らない
- **17cm はフルオート機が標準対応するサイズ**。既製機のカムがそのまま使える
- 45回転もフルオート機の標準機能

> 歴史上のジュークボックスが7インチシングルを使ったのは、まさにこの理由による。**今回の仕様確定は技術的に非常に筋が良い判断**で、機構の難度とコストを大きく下げている。

## 2-2. 課題は「レコードチェンジャ」1点に集約された

残る技術課題は、**15〜20枚のマガジンから1枚を取り出し、水平のプラッタに載せ、再生後に戻す**こと。ここに難度・工数・コストのほぼ全てが集まる。

以降、設計の中心はこのチェンジャ機構になる。

## 2-3. フルオート機を使うことの制約（設計に効く）

| 制約 | 内容 | 対応 |
|---|---|---|
| プラッタ径が盤より大きい | 一般的なフルオート機のプラッタは 28〜30cm。7インチ盤（17.8cm）より大きい | **盤を下から支えて載せることができない。必ず「上から置く」設計になる** |
| 起動が手動ボタン | STARTボタンを人が押す前提 | ボタン接点にフォトMOSリレーを並列接続して電気的に叩く（機械的にソレノイドで押すより確実・静か） |
| 終了信号が出ない | 「演奏終了」を外部に知らせる端子がない | アームレスト位置にフォトマイクロセンサを追加して検出（最も確実）。プラッタ回転停止の併用も可 |
| 民生用のデューティ | 常設商用（1日20〜50回）を想定していない | **同一機種を3〜4台まとめて確保**（予備機・保守部品取り）。針の入手性を機種選定の最優先条件にする |

## 2-4. 7インチの「38mm大穴」について

ドーナツ盤の中心穴は**38mm**。7mm穴の盤と比べて、ロボットにとって圧倒的に扱いやすい。

- **スピンドルに38mm用の固定アダプタ（円錐テーパ付き）を常設**すれば、盤を落とし込む位置決め公差が **±数mm** まで緩む
- 掴む側も、この38mm穴に**拡張式マンドレル**を差し込んで内側から掴める。**盤の再生面に一切触れない**

→ ただし**v3では中心穴把持を採らない**（A/B反転と両立しないため）ので、この利点は「スピンドルへの落とし込み公差が緩い」という点だけが残る。円錐アダプタは自動調心の保険として残す。

# 3. レコードチェンジャ機構（観覧車式）

> **v4での変更**：マガジンを**積み上げ式 → 観覧車式（垂直保管・回転割出し）**に変更。あわせて「タクトは遅い方が演出的に良い」という判断を受け、速度のための機構（Zのカウンタウェイト）を全廃した。
>
> **観覧車式は手元のRI-1G（Rowe AMI）実機と同じ方式**。実機と回路図18枚が一次資料として使える。

## 3-1. なぜ観覧車式か

| 項目 | 積み上げ式 | 観覧車式 |
|---|---|---|
| 選盤軸 | 直線Z 300mm（ガイド＋ねじ＋錘） | **回転割出し（軸受＋ウォーム）** |
| 昇降軸 | 上記と兼用 | **Z 100mm**（取り出しと載置のみ） |
| 保管姿勢 | 水平 — 皿状変形のリスク | **垂直 — 変形しない** |
| 棚の構造 | ラベル受けボス＋リム受け ×20 | **円弧溝＋上部ガイド（溝だけ）** |
| 盤への接触 | ラベル・リム | **こば のみ** |
| 取り出し | 水平に引き抜く（摩擦あり） | **真上に持ち上げる** |
| 反転 | θ軸を専用に追加 | **起立用θ軸と兼用（実質タダ）** |
| 外形 | 400H × 246D × 180W | φ506 × 210H |

軸移動距離が短くなるだけでなく、以下の副次効果が大きい。

1. **垂直保管はレコードの正しい保管法**。水平積みの副作用（自重による反り）を打ち消すために設計していたラベル受けボスとリム受けが、方式変更で丸ごと不要になる
2. **こば以外どこにも触れない**。接触ルール（§3-2）が構造的に満たされる
3. **盤は垂直で出てきて水平で再生される＝どうせ90°起こす必要がある**。その軸を270°まで回せばB面が上になる。**反転機構が実質タダ**
4. 筐体シルエットが横に太る → 1970年代の丸い意匠にむしろ合う

## 3-2. 接触ルール

| 部位 | 寸法 | 接触 |
|---|---|---|
| ラベル部 | φ89以内 | 可 |
| 音溝域 | φ92〜φ174（両面） | **厳禁** |
| 最外周リム | 幅約2mm | 可 |
| こば（厚み側面） | t1.5 | 可 |
| 中心穴 | φ38.1 | 可だが反転と両立しないため使わない |

**底面に爪を掛けて持ち上げる方式は失格。** プラッタのマットは全面接触するがこれは正常（禁じるのは点接触・線接触で荷重を受けること）。

## 3-3. マガジン諸元

- **20枚 / 18°等配 / ハブ半径75mm / 外形φ506 × 高さ210mm**
- 各スロット＝**盤の外周に沿った円弧溝**（こばの線接触で受け、半径方向の位置も溝が決める）＋ 倒れ止めの上部ガイド
- **ハブ付近のすきまがこの方式唯一の制約**

| 枚数 | ハブ半径 | 外形 | ヨーク片側すきま | 評価 |
|---|---|---|---|---|
| 20 | R75 | φ506 | 6.2mm | **推奨** |
| 20 | R60 | φ476 | 3.9mm | 可だがきつい |
| 15 | R60 | φ476 | 7.1mm | 余裕あり |
| 20 | R45 | φ446 | 1.5mm | 不可 |

## 3-4. 難所1：取り出し — 口開きの幾何

C字ヨークで φ178 の盤を掴むには、口が盤を通せるだけ開き、かつ閉じたら抜けない必要がある。

- ローラ配置：R1=真上、R2/R3=下方 ±75°
- **開 R100 → 口 193.2mm**（φ178 が通る・片側すきま7.6）
- **閉 R89 → 口 171.9mm**（φ178 が通らない＝**形状拘束**）
- 通過限界は接触半径 R92.1

**摩擦が抜けても盤は口から出られない。** 観覧車式では盤が垂直なので、この形状拘束の方向がそのまま落下方向になり、方式との相性が良い。

補足：3点は等配（120°）でなくてよい。**3つの接触点が同一半径の円上にあれば盤は必ず同心に決まる**ので、R1／±75°でも自動調心は成立する。

## 3-5. 把持ヘッド：ばね閉じ ／ カム開き（回転部に配線0本）

v3ではヨーク上にモータを載せ、θ軸を越えるたわみ配線で逃がす設計だった。**反転が難所である最大の理由がその配線**だったので、動力を外に出して根本から消した。

- **ねじりばねが常に閉じ側に付勢**。閉じるのはばね
- **開くのはキャリッジ側のPM-G＋カムフォーク**が、ヨークの開きレバーピンを押したときだけ
- **カムが噛むのは θ=0° のときだけ** → 搬送中・反転中に誤って開く事故が原理的に起こらない
- **θ軸を越える配線は0本**。180°往復による断線という故障モードが存在しない
- 把持力はばね定数で決まる（片側3N、3点で摩擦8.1N、盤の自重0.4Nに対し安全率20）
- 把持確認は θ=0° 位置でレバーピンを見る**固定側センサ**
- 停電・非常停止でも盤は掴まれたまま
- **要追加**：保守用の手動解放レバー（停電時に手で外せるように）

## 3-6. 難所2：反転 — 起立と反転の統合

**θ軸はマガジンの半径方向に置く。**

| θ | 姿勢 |
|---|---|
| 0° | 垂直（マガジン姿勢） |
| 90° | 水平・**A面が上** |
| 270° | 水平・**B面が上** |

水平姿勢でヨークが盤の横に来るので、上下を塞がない。プラッタへの載置と演奏後の掴み直しがそのまま成立する。

- **掃引空間：θ軸まわりに φ270 が必要**。マガジンの真上では下半分が干渉するので、持ち上げたあとY方向へ退避し、マガジンとプレーヤーの間の専用位置で回す
- **ここが一番の見せ場**。窓を切って照明を当てる価値がある
- ウォームが自己保持するので、反転途中で停電しても盤はその姿勢で止まる
- **マガジンへ返す前に必ず θ=0° へ戻す**（戻し忘れるとA面とB面が入れ替わる）

## 3-7. 駆動構成（パルスモータ5本）

| 軸 | 駆動 | ストローク | 無励磁時 |
|---|---|---|---|
| C 割出し | PM＋ウォーム1/40 | 18°×20 | 自己保持 |
| Y 前後 | PM＋タイミングベルト | 300mm | 水平・外力なし |
| Z 昇降 | PM＋台形ねじ | 100mm | 自己保持 |
| θ 起立/反転 | PM＋ウォーム1/30 | 0/90/270° | 自己保持 |
| G 開き | PM＋カムフォーク | 半径11mm | ばねで閉保持 |

### タクトを急がないことで消えた部品

v3では盤交換を15〜20秒に収めるためZ軸をベルト＋カウンタウェイトにしていた。急がなくてよいなら**台形ねじの自己保持で足りる**ので、錘・プーリ・ワイヤが丸ごと不要になる。観覧車式でZストロークが300→100mmに縮んだことも効いて、Z軸は事実上「小さな上下ユニット」になった。**遅くてよいという判断が、そのまま部品点数の削減になっている。**

### オープンループの代償（要作り込み）

サーボを使わない＝位置のフィードバックが無い。**脱調しても機械は気づかない。**

- 全軸に原点センサ（フォトマイクロ）。電源投入時は必ず全軸原点復帰
- C軸には各スロットの確認センサ
- 把持は θ=0° 位置のレバーピンセンサで判定
- 動作完了ごとに照合し、食い違ったら即停止して管理画面にエラー
- **この作り込みを省くと、ジャムに気づかず盤を割る**

## 3-8. 通し動作と載置

1. C割出し → 2. ヨーク降下（開）→ 3. カム戻し・ばねで閉じ → 4. Z持ち上げ30 → 5. Y退避・θ回転（A面90°／B面270°、約6秒）→ 6. 載置・開放・START

- 径方向に掴んでいるので、**盤をマットに接地させてから開放できる**（落とさない）
- 演奏後に平置きの盤を掴み直すため、プラッタに**φ150・厚さ8mmのマット**を噛ませ縁を14mm張り出させる
- **マット厚8mm分だけ盤が持ち上がるので、トーンアーム高さ（VTA）の再調整が必須** → アーム高さを調整できる機種を選ぶこと（機種選定の必須条件）

## 3-9. 盤交換時間

**30〜40秒**（往復するため）。タクトは遅くてよいという判断なので、これは仕様とする。

ただし**30〜40秒は無音の時間**になる。観覧車の割出しと反転を**窓から見せる前提**で設計する。選んだ盤が回ってきて、持ち上がり、くるりと反転する——**この一連が見せ場になるなら、遅さは欠点ではなく価値になる**。照明演出と進行表示はセットで考える。

# 4. 音響系（アンプ＋2.1スピーカー）

## 4-1. 信号経路

```
 カートリッジ(MM) → フォノEQ(RIAA) → 2.1ch DSPアンプ → [L] [R] [Sub]
        │                 │                │
    シールド線        シールド筐体      I2C ← Raspberry Pi（音量・EQ・ミュート）
   （最短配線）     （プレーヤー直近）
```

- **Raspberry Pi を音声信号経路に入れない**。Piの役割は I2C 経由の設定・音量・ミュート制御のみ。起動待ちや処理負荷が音に影響しない構成にする
- 2.1chには**アクティブクロスオーバーが必須**。ならばDSP内蔵のクラスDアンプモジュール（ADAU1701系／TAS5805M系）を使い、クロスオーバー・EQ・**リミッタ**・音量を一括で持たせるのが最も合理的
  - リミッタを入れておくと、**誰が最大音量にしても破綻しない**。常設商用機では実質必須
  - 純アナログ主義とは反するが、サブウーファーを積む時点でクロスオーバーは避けられない。**ここは割り切る**

## 4-2. 最大の技術リスク：ウーファー振動による音飛び

**DIYジュークボックスが失敗する原因の第1位がこれ。** 低音がキャビネットを揺らし、その振動が針に返って音飛びする。正のフィードバックになると演奏が続かない。

対策（**すべて実施する前提で設計する**）：
- プレーヤーを**防振マウント（シリコンゲル／ゴムアイソレータ）でフレームから絶縁**して浮かせる
- **ウーファーは独立した密閉サブチャンバー**に入れ、そのチャンバー自体もフレームから防振して縁を切る
- ウーファーとプレーヤーを**物理的に最も遠い位置**に配置（ウーファー下部・プレーヤー上部など）
- DSPで**40Hz以下をハイパスカット**（7インチシングルに40Hz以下の音楽情報はほぼ無い）
- **設置後に実機で追い込む工程を工数に見込む**。机上計算では詰め切れない

## 4-3. 第2のリスク：フォノ微小信号へのノイズ混入

カートリッジ出力は約5mV。ステッピングモータ・スイッチング電源・クラスDアンプは、すべて強力なノイズ源。

- **フォノEQはプレーヤー直近に置き、シールドケースに入れる**。EQ後のライン信号（数百mV）で引き回す
- グランドは**一点アース**。ループを作らない
- **モータ電源と音響電源のトランス／電源を分ける**
- **運用ルールで解く**：
  - **演奏中はチェンジャの全モータを完全に消磁（無励磁）**する
  - **チェンジャ動作中はアンプをミュート**する
  → この2つを守れば、モータノイズは原理的に音に乗らない。**制御シーケンスに組み込む**

# 4-4. 上部展示線（Nゲージ アメリカ型SL）

> **検討中の追加要素**：筐体上部にNゲージのアメリカ型SLを周回させる展示線を設ける案。事業化決定ではなく、意匠・演出上の検討事項として整理する。

## 走行制御は最短構成でよい

「一気に12Vを掛けてスタートダッシュしてよい」「停止位置は不問」という前提により、速度プロファイル制御・ブレーキ点センサ・駅センサは不要。**Pico→トランジスタ→リレー→線路**という最短構成で足りる。ただしリレーを使う以上、以下3点は速度制御の有無と無関係に必須。

- リレーコイルの**フライバックダイオード**（逆起電力からPico/トランジスタを保護）
- 線路手前の**ポリスイッチ（0.5A自己復帰）**（脱線・ショート対策）
- 機関車側の**コンデンサ＋フェライト**（ブラシのアーク放電によるノイズ抑制）

## 走行区間はチェンジャの盤交換中に限定する（確定方針）

当初案（演奏中に走行、曲終了で停止）は取り下げ、**走行区間をレコードチェンジャの盤交換シーケンスと完全に一致させる**方式を採る。

| | 信号 | 備考 |
|---|---|---|
| **SL走行 開始** | アーム原点復帰（曲終了検出） | 既存信号 — チェンジャの返却シーケンスを起動する信号と同じ。新規センサ不要 |
| **SL走行 停止** | プレーヤーSTART接点作動の**300〜500ms前** | 既存信号 — チェンジャ制御で既に使用（rev.4機構図 §8 step6）。前倒しはリレーOFF時の過渡現象を収めるため |

**この窓は、§4-3で定義した「チェンジャ動作中はアンプをミュートする」窓と完全に一致する。** つまり：

- **演奏中（針が溝に乗っている間）はSLの電源が物理的にOFF** → フォノへのノイズ混入が音として問題になる経路が構造的に消える
- SLが走る区間は元々アンプがミュートされているので、多少のノイズが乗っても実害が無い
- 観覧車の割出し・反転とSLの周回が同じ時間に動くため、**盤交換30〜40秒の無音区間の見せ場として機能を統合できる**（機構が動くのを見せる、という本機の一貫したテーマに沿う）

## それでも外さない対策

演奏中の混入リスクは構造的に下がったが、**この前後関係はハードウェアのインターロックではなくソフトウェアの前提**であることに注意。SL停止コマンドの遅延・欠落があれば、演奏中にSLが動く事態が起こりうる。

- Phase 1で異常系（SL停止コマンドが届かない場合の挙動）を検証すること
- フェイルセーフとして、**START接点作動をSL電源のハード的なOFF条件にも配線する**（AND条件）案を検討する価値がある
- 機関車側スナバ・配線分離・展示線とプレーヤーの物理的な距離確保は、演出上／保険として継続する

## ノイズ伝達の仕組み（参考）

線路（周長約1.56m）は電流ループを形成し、リレーの開閉やブラシのアーク放電で電流が急変すると、その変化がループ周囲に磁界を作る。近くのフォノ配線（これも小さなループを持つ）がこの磁界を拾うと誘導ノイズになる（磁気結合）。もう一つ、トレイン電源とオーディオ電源のグランドを共有すると、スイッチング電流がグランド線にわずかな電位差を作り、それがフォノの基準電位を揺らす（共通インピーダンス結合）。対策の多くはこの2経路のどちらかを断つもの：距離を取る・配線をツイストする（磁気結合対策）、電源とグランドを分離する（共通インピーダンス対策）。

## 検討事項

- 大型アメリカ型SL（4-8-4・関節式等）はR249を通らない機種がある。**車両選定前にカタログの最小通過半径を要確認**
- 編成は機関車＋貨車2両程度の短編成に留める（起動衝撃・減速時の押されによる脱線対策）
- 展示線ユニットは引き出し可能な構造とし、線路の清掃を運用に組み込む
- この要素はジュークボックス本来の機能（音楽再生）には寄与しない。**「見て楽しむ機械」としての演出価値と、保守項目・リスクの増加を天秤にかけた判断**であることを認識しておく

# 5. 制御アーキテクチャ

```
 [100円コインセレクタ]──パルス──┐
 [選曲ボタン ×20（照光式）]      │ I2C（MCP23017 ×2：入力20＋LED20）
 [クレジット表示]                 │
                                   ▼
                        ┌────────────────────────┐
                        │  Raspberry Pi 5          │
                        │  ・選曲UI／キュー管理      │
                        │  ・曲目DB／売上ログ        │
                        │  ・7インチ操作モニタ       │
                        │  ・DSP制御（I2C）          │
                        │  ・照明演出                │
                        └───────┬────────────────┘
                                │ UART（コマンド／ステータス／ハートビート）
                        ┌───────▼────────────────┐
                        │  RP2040 (Pico) または PLC │
                        │  ・Z/Y/グリップ軸制御       │
                        │  ・原点復帰／インターロック   │
                        │  ・ジャム検出／安全停止      │
                        └───────┬────────────────┘
        ┌────────────┬─────────┴──────────┬──────────────┐
   ステッピング      グリップ            センサ入力         接点出力
   ドライバ×2〜3   （ソレノイド／      （原点×3、盤有無×2、  （プレーヤーSTART、
   (TMC2209等)      サーボ）            アームレスト、扉）    アンプミュート）
```

## 設計判断
- **Piにリアルタイムのパルス生成をさせない**。Linuxは軸制御に向かず、脱調と異音の原因になる。上位（UI・DB・通信）＝Pi、下位（軸制御・安全）＝Pico or PLC で分ける
- **RIGELの本業がPLCであることを踏まえると、下位をPLC（FX5U級）で組む選択は有力**。RTS教材への転用を視野に入れるなら、むしろPLC版の方が資産価値が高い（§8）
- Pi↔下位間は**ハートビート監視**。Piが落ちても機構は安全側（全軸停止・励磁OFF）に倒れること

## 選曲ボタンの構成
- 20枚＝**20個の照光式押しボタン＋タイトルカード**を推奨。テンキー入力より直感的で、1970年代の意匠にも合う
- GPIO直結では足りないので **MCP23017 ×2**（入力20点＋LED20点）を I2C で。配線も減る
- B面対応（§3-2）を入れるなら **A/B切替ボタン1個を追加**するだけで40曲に対応できる

## 安全設計（省略不可）
- 非常停止押ボタン（機械接点でモータ電源を直接遮断）
- 扉／カバー開時のインターロック（PET扉にセーフティスイッチ）
- 全軸の原点復帰シーケンス。原点未確立時は動作禁止
- ジャム検出（軸の位置決め時間超過、盤有無センサの不整合）→ 安全停止＋管理者通知
- AC100V部は絶縁・接地・PSE適合部品。ロジック／音響部と物理的に区画分離

# 6. 操作パネル（本体モニタ ＋ 暗証番号）

> **v2からの変更**：Bluetooth管理は廃止。本体に7インチタッチモニタを搭載し、管理者は暗証番号で設定画面に入る方式に変更した。

## 6-1. 構成

- **7インチ静電容量タッチモニタ**（1024×600／DSIまたはHDMI）を前面パネルに開口して直接搭載。PETパネル越しではタッチ精度が出ないため、開口すること
- Raspberry Pi 上で **Chromium を kiosk モードで起動**し、ローカルのWebアプリを常時表示
- **通常画面**：曲目リスト、クレジット残、再生中の曲、機構ステータス
- **管理モード**：画面右下隅を3秒長押し → 暗証番号6桁 → 管理メニュー

## 6-2. 管理メニューの項目

- 曲目登録・棚割付（No.01〜20にどの盤を入れたか）
- 価格設定／音量上限／営業時間／無料再生
- 売上集計／動作ログ／エラー履歴
- 原点復帰／手動ジョグ（**扉インターロックが閉の時だけ有効**）

## 6-3. Bluetoothを廃したことの効果

| 項目 | 効果 |
|---|---|
| 端末依存 | **管理者の端末に依存しない**。iOS の Web Bluetooth 非対応という制約が丸ごと消える |
| 電波 | Pi の Wi-Fi と Bluetooth が2.4GHz帯を取り合う問題が無くなる |
| 現場調整 | **機構を手動ジョグしながら画面を見られる**。実務上これがいちばん効く |
| 引き換え | **画面が誰でも触れる場所にある** → 暗証番号と操作ログが必須になる |

## 6-4. セキュリティ・運用上の必須事項

- **暗証番号を平文で保存しない**。ハッシュ＋ソルトで保持する
- **初期値（0000等）のまま出荷しない**
- **5回失敗で10分ロックアウト**。電源再投入でも解除されないこと
- 管理モードの**全操作をタイムスタンプ付きで記録**する（売上と無料再生に触れるため）
- **OSのデスクトップ・アドレスバー・タスクスイッチャを一切出さない**
- **USBポートは筐体内に隠すか無効化**する。キーボードを挿されると kiosk を抜けられる
- 管理モードへの入口は画面に表示しない（長押しという「知らないと辿り着けない操作」に隠す）

# 7. 開発フェーズ（小さく作る）

## Phase 1：チェンジャ無しの完動機（最優先・2〜3週間）
レコードは**人が1枚セットする**。それ以外は全部作る。

- コイン投入 → ボタン選曲 → STARTを電気的に叩く → 演奏 → 終了検出 → クレジット処理
- アンプ2.1ch・スピーカー・**防振・ノイズ対策の実機追い込み**
- 7インチモニタの操作画面（通常画面＋暗証番号つき管理モード）
- Pi＋Pico の上位下位分担の確立

**この時点で「ジュークボックスとして遊べる」状態になる。**
そして **§4-2（音飛び）と §4-3（ノイズ）という2大リスクを、機構を作る前に潰せる**。ここを先にやるべき最大の理由。

## Phase 2：チェンジャ機構（4〜8週間）
- Z・Y・グリップの3軸、20段マガジン
- 盤ハンドリングの信頼性検証（**100サイクル連続試験で無傷・無ジャムを確認**）
- ジャム復旧手順の確立

## Phase 3：筐体・意匠・仕上げ
- アルミフレーム＋PETカバー、照明演出（WS2812B）、タイトルカード
- 古民家（源氏車）に設置して実運用

## Phase 4（オプション）
- θ軸追加によるB面再生（20曲→40曲）
- Wurlitzer型の「見せる」チェンジャへの意匠強化

# 11. 事業観点の補足（v1評価からの更新）

仕様確定により、技術リスクと工数は **v1想定より下がった**（オートキュー自作の消滅、7インチ盤の調達容易性、38mm穴の恩恵）。一方で、v1で指摘した事業面の評価は**変わっていない**。

- **運用保守コストの重さ**（針・盤・ホコリ・客の扱い）は依然として最大の構造的弱点
- **継続収益の道筋**（保守契約／レンタル／コンテンツ供給）が未定義なのも変わらない
- **RIGELだからできる**という優位（機構＋制御＋筐体の一貫設計）と、**技術資産の蓄積**は引き続き高い評価

そして今回の構成は、**RTS教材への転用適性がv1案よりむしろ上がっている**。

理由：チェンジャがZ・Y・グリップという**教科書的な直交ピック＆プレース**になったこと。
ここに 割出し・原点復帰・位置決め・センサ・ジャム検出・安全回路・上位連携（PLC×Raspberry Pi）・課金HMI が全部入る。**しかも動作結果が「音楽が鳴る」という形で即座に体感できる**——教材としてこれは相当に強い。

→ **下位制御をPLCで組み、軸・センサをユニット単位で切り出せる構成にしておくこと**を、改めて推奨する。1台の投資が2事業に効く。
